# Policy and history contracts V3

V3 is the live-only successor to the immutable snapshot-backed V2 policy
lineage. V2 bytes and behavior are unchanged.

`HistoryAvailabilityBindingV1` is a closed, content-addressed tagged union. Its
only modes are `snapshot_baseline` and `historical_no_go`. The latter pins the
accepted M1 commits, four sealed evidence hashes, frozen tournament scope,
cutoff/windows/patch, terminal outcome, and the complete byte-sorted disabled
family set. It cannot carry snapshot or baseline fields. Decoders reject
unknown/duplicate fields and non-RFC-8785 bytes. Its canonical size ceiling is
64 KiB.

`PolicyLineageManifestV3` preserves all non-history fields and the 2 MiB bound
from V2, replacing direct snapshot/baseline fields with one binding ID and
SHA-256. `PolicyCommitV3` and `PolicyCheckpointV3` preserve V2 semantic,
ordering, cardinality, and size rules (256 KiB and 16 MiB respectively), while
requiring V3 schema tags and a V3 manifest identity on every frame.

`HistoricalUnavailableFixtureV1` carries one valid complete ten-player live
observation, the typed state `unavailable`, the exact binding/lineage
identities, and all eight disabled families. It has no baseline field.
`LiveOnlyReleaseBindingV1` pins the release source, lineage, history evidence,
scope, and rule/config/catalog/terminology/localization identities. Both fixed
shapes are limited to 64 KiB canonical JSON.

The V3 commit log stores `history-binding.v1.json` and `lineage.v3.json` before
opening the first `.pcl3` segment. Each file is validated, written and synced,
atomically renamed in the same directory, then protected by a parent-directory
sync. Missing or substituted retained content and mixed `.pcl`, `.pcl2`, and
`.pcl3` lineages fail closed. Raw capture is outside this adapter and remains
independent.
