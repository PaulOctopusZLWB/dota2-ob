# Policy recovery contract set V2

This document is normative for the V2 policy-recovery types in
`internal/contracts` and the durable adapter in `internal/policy/commitlog`.
The accepted program specification at commit
`235e65e76ef655be7dc860ff20718b9a4541f51b` remains the higher-level source of
truth. The V2 JSON examples and adjacent SHA-256 files are executable canonical
goldens.

V2 replaces only `PolicyCommitV1` and `PolicyCheckpointV1` as production
restart formats. The five primary contracts—`LiveObservationV1`,
`HistoricalBaselineV1`, `InsightCandidateV1`, `BroadcastDecisionV1`, and
`OverlayStateV1`—remain byte- and semantics-compatible. V1 recovery records
remain immutable compatibility evidence and are never mixed with V2 frames.

## Lineage manifest

`PolicyLineageManifestV2` is canonical RFC 8785 JSON bounded to 2 MiB. Its ID
and SHA-256 are both the lowercase SHA-256 of its canonical bytes. It binds:

- the session, raw-record schema and framing, raw-payload schema, live schema,
  and projection mapping;
- the tournament scope and historical snapshot by content identity, plus the
  ordered eligible baseline hashes;
- rules, config, catalog, terminology, localization-parameter mapping, and
  pure-engine build by version and content hash.

The adapter writes the manifest through an exclusive same-directory temporary
file, file sync, atomic rename, and parent-directory sync before the first V2
frame. Existing frames without the manifest, a substituted manifest, or a
manifest write failure fail closed. The manifest does not hash the growing raw
session log; each observation commit supplies its own immutable content binding.

## Commit causal inputs and framing

`PolicyCommitV2` is bounded to 256 KiB. Exactly one causal input is present:

- an observation sequence, the exact `EvidenceRefV1`, accepted raw-record
  SHA-256, and canonical `LiveObservationV1` SHA-256; or
- a command ID, complete canonical `OperatorCommandV1`, and its terminal
  `OperatorCommandResultV1`.

The commit also carries lineage identity, contiguous commit sequence, prior and
resulting policy revision/state hashes, resulting observation and policy-time
high-water marks, ordered decisions and audits, and the terminal publication
outcome. Nested session, command, revision, evidence, and result identities are
validated before persistence.

V2 frames are `uint32 big-endian length || canonical payload || SHA-256(payload)
|| "PCOMMIT\x02"`. Segment names are the first commit sequence followed by
`.pcl2`; segments roll at 10 MiB. A completed frame is synchronized before
`Append` returns. A write or sync failure truncates and synchronizes to the
prior verified offset; an unverifiable rollback seals the log. Recovery
truncates only an incomplete final tail and rejects a terminated invalid frame,
sequence/state discontinuity, duplicate command ID, wrong lineage, or mixed V1
frame.

## Semantic state and application locators

`policy_state.v2` contains only pure semantic state:

- complete preview candidates in deterministic rank order and the optional
  complete active candidate/latest decision;
- sorted disabled rules, cooldowns, pins, emergency-hide state, policy
  revision, observation high-water, and policy-time high-water;
- up to 4,096 candidate tombstones ordered by suppression deadline then
  candidate ID; and
- up to 4,096 semantic idempotency entries ordered by command ID. Each entry is
  exactly `(command_id, SHA256(canonical OperatorCommandResultV1))`.

Preview ranks by priority descending, confidence descending, first evidence
time ascending, rule version ascending, then candidate ID ascending. Preview
and pins are bounded to 64; disabled rules and cooldowns to 256; tombstones and
semantic command results to 4,096. Policy-owned identifiers are at most 128
UTF-8 bytes.

`PolicyCommandLocatorV2` is an application cache containing command ID, segment
ID, byte offset, commit sequence, and frame SHA-256. Locators, checkpoint
creation time, and checkpoint commit/hash anchors are excluded from
`policy_state.v2`. Consequently, a first command's semantic result and state
hash are computable before sequence/location assignment and frame hashing.

Duplicate lookup resolves the locator, validates the complete frame, and
requires the frame command ID plus canonical result hash to equal the semantic
entry. The tables are one-to-one. Missing, duplicated, substituted, corrupt, or
mismatched locators fail closed; missing checkpoints rebuild both tables from
committed frames.

## Checkpoint and recovery

`PolicyCheckpointV2` is canonical JSON bounded to 16 MiB. It carries the
complete semantic state, the cache-only locator table, and an explicit anchor:
lineage ID/hash, session, commit sequence, referenced frame SHA-256, policy
revision/state hash, observation high-water, and policy-time high-water.
Validation recomputes `policy_state.v2` and cross-checks every anchor field
against the referenced frame.

An unreadable, noncanonical, or semantically invalid optional checkpoint falls
back to full committed-frame replay. A structurally present invalid locator
table fails closed because it is an attempted direct-result cache, not semantic
state. A valid checkpoint returns only later frames for deterministic
continuation.

`VerifyReplayV2` keeps application source resolution outside the adapter. For
an observation it calls the application-provided lineage/raw/projection
verifier before the pure re-evaluator. The verifier must load the named accepted
raw record, validate the evidence/raw hash, reproject with the manifest-selected
mapping, and compare the canonical live-observation hash. Any mismatch stops
before evaluation. Command frames expose the complete embedded command to the
command verifier and re-evaluator. Re-evaluation must compare the reproduced
result, decisions, audits, publication, revisions, high-water marks, and state
hash byte-for-byte with the committed record.

Production recovery never searches alternate artifacts until a hash happens to
match. A V1 command lineage is non-convertible without a separately
authoritative, complete, content-bound command journal; missing action, target,
revision, or policy time is never synthesized.
