# TI analytics contract set V1

This document is normative for `internal/contracts`. The Go types, validators,
golden JSON, and adjacent `.sha256` files are the executable source of truth.
A breaking field or semantic change requires a new schema version; V1 fields
are never repurposed.

## Encoding, units, and compatibility

Persisted and golden records use UTF-8 RFC 8785 JSON: object properties are
sorted by UTF-16 code units, strings use the required minimal JSON escapes, and
there is no trailing newline in the canonical byte sequence. Golden files have
one filesystem newline for readability; tests trim that newline, compare every
canonical byte, and verify the pinned SHA-256. Readers accept any valid JSON
property order, reject unknown fields/trailing values, and re-emit the pinned
canonical form.

JSON numbers are signed/unsigned integers in documented units and within the
RFC 8785 interoperable integer range. Durations and policy time use integer
milliseconds; coverage uses integer parts per million. Fractional domain
quantities use `Decimal`, a locale-independent string with exactly three
fractional digits (for example `"650.000"`). Persisted contract types contain
no float or map fields. Arrays are ordered; set-like arrays validate their
documented total order and uniqueness.

`ObservedV1` separates source state from value. Its state is `present`,
`absent`, `redacted`, `unsupported`, or `invalid`; `value` exists only for
`present`. Provider-supplied zero and false therefore remain distinct from a
missing field. UTC RFC 3339 timestamps describe source/storage time; policy
time is always explicit integer milliseconds.

Snapshot validation requires the active match in the excluded set with reason
`active_match`, every included match completed and identity-verified, replay
SHA-256 present, maximum source-event time equal to the latest included fact,
and snapshot scope/cutoff equal to the sealed tournament scope. Quarantined or
unresolved identity never becomes an included fact. Baselines validate their
identity in the manifest and all scope/session/active-match identities.

## Policy and recovery ports

`OperatorCommandV1` freezes these actions: `approve`, `show`, `reject`, `pin`,
`unpin`, `emergency_hide`, `clear_emergency_hide`, `disable_rule`, and
`enable_rule`. Candidate actions require exactly one candidate target, rule
actions require exactly one rule target, and emergency actions accept no
target. Accepted command results advance revision exactly once; rejected
results do not mutate it.

`PolicyCommitV1` admits exactly one causal observation sequence or command ID,
validates every nested decision/result/audit record, and enforces session,
command, revision, and publication coherence. `PolicyCheckpointV1` contains
the bound snapshot, last observation sequence, policy revision, up to 4,096
ordered idempotent command results, up to 64 preview candidates, cooldowns,
pins, and emergency-hide state. `ValidateAgainstCommit` binds its sequence,
revision, state hash, observation high-water mark, and canonical commit hash.
The checkpoint remains an optional cache; the committed policy log is the
source of truth.

## Overlay text and privacy

Title and body limits are Unicode code-point limits, not UTF-8 byte or grapheme
cluster limits: title 160 code points, body 1,024 code points. This choice is
stable for Chinese fixtures and deterministic without a Unicode segmentation
dependency. Exactly 160 Chinese code points are accepted. C0/C1 and other
Unicode control characters, bidi marks/overrides/isolates, `<`, and `>` are
rejected. Visible states require decision identity, non-empty ordered evidence,
confidence, and source receive time. Hidden states contain no claim and require
a stable health code.

## Canonical legacy path and dependency direction

The executable compatibility direction is:

`session.Record + raw payload -> LiveObservationV1 -> capture-owned evidence resolver -> legacy NormalizedTick`.

Live analytics and the CLI rebuild traverse that path. The adapter verifies
the evidence identity and raw SHA-256, reconstructs every public field from the
observation, and resolves account IDs, Steam IDs, player handles, and the raw
observed-field footprint only inside capture. Existing raw, analytics, events,
summary, and diagnostic JSON shapes remain byte-compatible.

The recursive architecture test requires and examines `internal/contracts`,
`liveprojection`, `history`, `insight`, `policy`, `delivery`, `presentation`,
and `obscontrol`, including future subpackages. Each root has an explicit
internal-import allowlist, and unapproved third-party imports fail. The seven
future roots are declaration-only in M0: no parser, database, network, OBS,
delivery, insight, or policy production behavior is introduced here.
